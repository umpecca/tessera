Follow-up: the [graphics investigation](terminal-graphics-reliability-2026-10-05.md)
adds verified canvas context-loss recovery for both renderers. The evaluated
CPU-canvas workaround was rejected; silent corruption and intermittent Chrome
graphics stalls remain unresolved. This does not change the native repair below.

Task 155 fixes the native memory crash found in the longer visible-browser test.
The native regression and build checks passed, and the crash did not recur in
the longer soak. Overall visual release validation remains failed: hardware
Chrome reproduced a presentation stall and a small classic-canvas corruption.

## Cause and repair

The pinned `PageList.initPages` relied on the native page allocator returning
zeroed memory in release builds. Zig's WASM page allocator recycles freed heap
allocations. A new terminal could therefore inherit cell data from an earlier
terminal, although `Page.initBuf` reinitialized its row offsets and metadata.
Interpreting those stale cells as styles or grapheme references could trap.

The pinned-source patch now clears initial and growing page buffers before
`initBuf`, including newly allocated pool items and capacity beyond a previous
layout. Initialization happens when a page is created; the character parser,
image cleanup, and browser painting paths retain their existing behavior.

The regression shares one WASM instance across 160 terminal creations and
disposals, then checks new blank cells, image attachments, combining/Devanagari
output, and snapshots across six further cycles. It fails with the old core:
a newly created cell contains codepoint 48,538 instead of zero. It passes with
the rebuilt core. The former test helper created an independent WASM instance
for every fixture, preventing it from detecting this reuse pattern.

## Longer visible validation

The same 10-minute headed Chrome test processed 2,279.92 MiB (~2.23 GiB) and
9,921 echo probes. All generated bytes and echoes drained in all three phases.
This is synthetic browser output using the production core/renderer/schedulers,
not a PTY/network end-to-end test. The Intel/ANGLE Direct3D 11 graphics path was
enabled, with no screenshots or pixel readbacks during timed load. A rolling
graphics trace ran, so these are diagnostic timings.

| Phase | Output | Echo median | Echo p95 | Worst echo |
| --- | ---: | ---: | ---: | ---: |
| Four large experimental panes / 4 min | 480.00 MiB | 4.8 ms | 8.5 ms | 24.3 ms |
| Four large classic panes / 3 min | 359.98 MiB | 10.2 ms | 22.6 ms | 311.6 ms |
| Eight panes at 8 MiB/s / 3 min | 1,439.95 MiB | 19.3 ms | 22.1 ms | 53.2 ms |

The following 160-terminal lifecycle exercise passed disposal validation. Its
eight-terminal creation median was 29.6 ms; write/paint/disposal median was
10.2 ms. All six image-plus-Unicode cases and the other Unicode/partial cases
passed after this churn, with no WASM memory traps or page errors.

Twenty-three of the 24 pixel checks passed. The first classic full-paint check
at 200% scaling failed with 30 altered pixels in an 8×4 region near the bottom
of the canvas, with channel differences up to 255. This is not the previously
documented one-unit readback rounding. All five later repeats of that case
passed. The test correctly exited nonzero; it is not overall release sign-off.

Four delayed echoes waited for the same classic frame. Parsing took 0.1–0.2 ms;
the longest parse-to-paint delay was 311.4 ms. The saved trace shows
`DXGISwapChainImageBacking::Present` blocking Chrome's GPU main thread for
360.433 ms in that interval. All four affected echoes were painted before trace
extraction began, so saving the capture did not cause this stall. The classic
phase had 18 long tasks (maximum 74 ms); the other phases had none.

A separate visible software-rendering control used one-second output phases,
the same lifecycle churn, and all 24 pixel checks. All passed with exact pixel
matches and no native errors. This supports investigating hardware Chrome's
graphics path for the corruption, but it does not establish the exact driver
or raster-cache cause. The runner now accepts `--graphics=software` and
`--pixel-repeats=6` for this diagnostic; product graphics defaults are unchanged.

The native crash fix is complete. The presentation stall and canvas corruption
remain unresolved, so hold the release tag pending graphics investigation.
